# 2026-07-21

- 修复 Tesseract.js OCR 提取文字失败的问题：
  - 根因：`createWorker` 默认使用 Blob URL + `importScripts` 加载 `worker.min.js`，在 `app://index.html` 页面中 Blob 的 origin 与 `file://` 资源跨域，导致脚本加载失败。
  - 修改 `src/utils/ocr.js`：改用相对于当前页面的 `./tesseract/...` 路径，并设置 `workerBlobURL: false`，让 Worker 直接通过 `app://` 协议加载，保证 worker、core WASM、语言数据均为同源，且由主进程协议处理器返回正确的 MIME 类型。
  - 清理 `electron/preload.js`：移除不再使用的 `distPath` 暴露。
  - 执行 `npm run build` 重新打包，`dist/bundle.js` 中已无 `file://` 引用。

- 修复复制图片到剪贴板在微信里粘贴为乱码的问题：
  - 根因：renderer 中的 `navigator.clipboard.write` 在自定义 `app://` 协议下不可靠，失败后会回退为写入 base64 data URL 文本，导致粘贴出乱码。
  - 修改 `electron/main.js`：新增 IPC `clipboard:copyImage`，使用 `nativeImage.createFromDataURL` + `clipboard.writeImage` 在主进程写入真正的图片到系统剪贴板。
  - 修改 `electron/preload.js`：暴露 `copyImage(dataURL)` 给 renderer。
  - 修改 `src/components/ReaderView.jsx`：图片复制优先调用主进程接口；保留非 Electron 环境的原有降级方案。
  - 执行 `npm run build` 重新打包。

- 修复书签/最近阅读打开后无法定位的问题：
  - 根因：
    - PDF 书签跳转使用硬编码 500ms `setTimeout` 触发 `jump-to-page`，PDF 页面可能尚未渲染完成，导致滚动目标元素不存在。
    - 最近阅读没有保存/恢复阅读进度；`reading-progress.json` 相关 API 已存在但从未调用。
    - EPUB/TXT 没有分页，也没有保存滚动位置。
  - 修改 `src/utils/storage.js`：`saveReadingProgress` / `loadReadingProgress` 增加可选 `scrollRatio` 字段，用于 EPUB/TXT 的滚动比例恢复。
  - 修改 `src/App.jsx`：
    - `openBook` 打开书籍时优先使用显式传入的书签页码，否则从 `reading-progress.json` 恢复进度。
    - PDF 打开时设置 `currentPage` 为保存/书签页码；EPUB/TXT 将 `scrollRatio` 附加到 book 对象传给 ReaderView。
    - 新增 effect：PDF 的 `currentPage`/`totalPages` 变化时自动调用 `saveReadingProgress`。
  - 修改 `src/components/ReaderView.jsx`：
    - PDF `loadPDF` 不再重置到第 1 页，而是使用 `currentPage` prop，并在 `renderAllPages` 完成后滚动到目标页。
    - EPUB/TXT 加载完成后调用 `restoreScrollRatio()` 恢复滚动位置。
    - 新增 EPUB/TXT 滚动防抖 effect，滚动停止后保存 `scrollRatio` 到 `reading-progress.json`。
  - 修改 `src/components/BookList.jsx`：书签点击时通过 `initialPage` 把目标页传给 `openBook`，移除不可靠的 `setTimeout` + `jump-to-page`。
  - 执行 `npm run build` 重新打包成功。
  - 注：验证运行时因本地 Electron binary 异常（`electron.exe --version` 显示 Node 版本，且 `require('electron')` 返回数组）未能启动；已恢复 `package.json`/`package-lock.json` 与测试文件，建议用户运行 `npm install` 恢复依赖环境。
